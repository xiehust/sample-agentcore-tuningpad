01 系统总览与架构介绍

TuningPad 是编排控制面，不是强化学习算法本身。它把区域资源、集群、Agent、数据集与训练配置组织成可追踪的任务；实际 GRPO（基于一组采样奖励的策略优化）训练交给 EKS 上的 Ray / verl，Agent 在 Bedrock AgentCore Runtime 中运行。

控制面：意图与进度

React 页面经 HTTP 提交操作；FastAPI 校验请求、记录对象，再交给后台 pipeline。SQLite 记录 ID、配置、stage 进度和指标；前端通过资源与 Job 轮询取得快照。

训练面：计算与采样

RayJob 承载训练。toolkit 的 AgentLoop 调用 AgentCore；Agent 的模型请求回连 rollout gateway，再到 vLLM。rollout 是 Agent 执行一条采样轨迹的过程，不是 FastAPI 接收结果的 webhook。

1.1 逻辑分层：不是一串必须经过的微服务

下面是代码职责，不是独立部署单元；后端各层仍在同一应用内协作。普通查询可直接返回，只有长操作才交给 Job。

  • 交互与 API 边界：页面收集选择、展示快照；router 校验输入、组织响应与启动任务，不负责完成 GPU 训练。前端预览不能替代后端校验。
  • 编排层：pipeline 定义业务阶段及收尾，engine 管排队、执行与进度；它们不实现梯度计算。Job 是执行记录，Run 是训练业务对象，二者不能混作一个状态。
  • 领域与适配层：services 装配资源操作；planner 给建议，render 将计划转成脚本和 Kubernetes 对象；生成配置不代表资源已经创建，更不代表训练成功。
  • 执行层：Ray / verl 承担训练，toolkit 接入 Agent 采样，AgentCore 执行 Agent。控制面设置这些契约，不替代外部引擎的内部实现。

扩展入口按责任选择，参见 模块边界；不要把整个系统理解为每个 HTTP 请求都经过全部阶段。

1.3 三条跨层流：控制请求、模型请求、产物读写

  1. 管理控制流：浏览器提交配置 → API 校验并保存 Run / Job → 后台调用 AWS / K8s 编排资源。返回 ID 表示任务已登记，不是训练已完成；后端查询云状态，浏览器再轮询台账。详见 任务语义、前端反馈。
  2. 训练采样流：Ray / verl 经 toolkit 调用 AgentCore → Agent 根据 _rollout 参数请求训练侧 gateway（模型请求入口）→ vLLM 推理；结果与奖励按 toolkit 契约交回训练侧。此流不穿过 FastAPI。回连依赖 VPC 网络，代码添加 AgentCore 安全组到 gateway 18765 的规则，但不证明实际可达；网关进程内部属于外部 toolkit，不能据此另画一个托管网关服务。详见 训练链路、网络边界。
  3. 产物数据流：训练脚本将 S3 数据拉到 FSx；训练写 checkpoint，并把日志 / 索引同步回 S3。后端读日志、解析指标写入 SQLite，页面读取摘要；模型权重并不随管理 API 轮询传给浏览器。

1.4 三种存储：不是同一份数据的三套副本

SQLite 是控制台台账：保存配置、外部标识、阶段进度、解析后的指标与日志游标，不保存云资源本身，也不是模型文件仓库。FSx 是训练侧共享文件系统：挂载为 /fsx，承载模型缓存、暂存数据及完整 checkpoint（恢复训练所需的检查点）。S3 是对象存储：承担构建输入、数据集与跨边界产物交换，不是运行中的共享目录。

1.5 从实现可见的取舍与扩展限制

以下是静态实现的收益 / 限制归纳，不是对作者历史决策意图的推测：

  • 本地线程池 + 台账：无需另部署消息队列，重启可从未完成阶段重跑；代价是长时间 monitor 占用工作线程，任务执行依赖后端进程。
  • 恢复不等于高可用：引擎没有跨实例任务锁或领取租约；进程内锁不能协调多个后端。不能据此宣称 HA（高可用）或 exactly-once（恰好执行一次），直接增加后端副本不是安全扩容方案。
  • 字段不等于隔离：workspace_id 虽存在，当前查询并未形成租户访问边界。多租户需另行设计鉴权与数据 / 资源隔离，不能仅启用该字段。
  • 启发式规划：纯函数按模型与实例参数给可解释建议，便于预览；它不验证真实空闲容量或完整显存需求，不保证配置可运行、更不保证收益。详见 规划与参数；恢复边界见 Job 引擎。

02 启动与模块边界

先把“启动本地控制台”与“创建云资源”分开。入口脚本管理进程；HTTP 请求和后台 stages 才承载业务操作。下面是行为解释，不是要求执行这些命令。

2.1 本地进程与后端 lifespan

  1. start.py 默认以独立进程组启动 Uvicorn（--reload，默认 8100）与 Vite（默认 5180），将 PID 和进程输出写到本地 .run/，再轮询 HTTP 就绪。--prod 分支先构建 UI，改用 Vite preview，Uvicorn 不再 reload；该参数本身不是 HTTPS 或生产安全部署方案。
  2. create_app() 装配路由、鉴权与异常处理。进入 lifespan 后先 validate_startup → init_db → _load_modules；开启后台工作时恢复未结束 Job，再调用 start_reconcilers()。退出时调用引擎 shutdown。
  3. stop.sh 读取已记录的进程组 PID，发送 TERM 并删除 PID 文件。它没有云清理调用，也不逐项取消 Run。JobEngine.shutdown() 取消尚未开始的 futures，不强制打断已运行 stage。

停止本地 ≠ 清理云端。RayJob、GPU 池、AgentCore、FSx 等不会因 stop.sh 自动销毁。后端 monitor 停止观察，不代表云端计算停止；资源清理必须另看 业务清理分支 和 独立保护的条件。

04 Job 引擎与状态

Job 是一次 pipeline 执行，stage 是其中一步，Run 是一次训练业务。例如 run.train Job 指向某个 Run；Run 的 image 阶段还可能等待另一个 trainer.build Job。它们共享台账，却不共享同一条状态机。

4.1 从注册到结束：引擎只负责执行骨架

  1. register(type, stages, on_finish) 保存有序阶段与可选 finish hook，拒绝同一 pipeline 内重复的 stage 名。stage 名是持久化进度的定位键，而非纯显示文案。
  2. start() 先提交 queued Job、payload 和全部 pending stages，再放进 ThreadPoolExecutor。默认工作线程数来自 max_concurrent_jobs（默认 12）；长时间 monitor 也占一个 worker。
  3. _run() 加载 context 与 succeeded 阶段集合，设置 Job 为 running，然后按注册顺序执行尚未成功的阶段。阶段成功/失败/取消分别写回 stage 状态与时间。
  4. _finish() 先调用业务 hook，再提交 Job 终态并清取消标记。AppError 的稳定 code / message 持久化到 Job，非预期异常将 traceback 写到 Job 文本日志。

hook 的先后顺序不是事务保证。引擎会捕获并记录 finish hook 异常，随后仍提交 Job 终态。因此“看到 Job 结束就必然看到目标资源已同步完成”不成立。引擎也没有分布式领取、租约或跨进程去重，不能承诺 exactly-once（严格只执行一次）。

6.2 参数的四层来源：显示继承不等于提交覆盖

  1. 后端基础默认：GET /api/runs/defaults 返回 DEFAULT_PARAMS 与 AGENT_LOOP_DEFAULTS。例如 train_batch_size=32、rollout_n=8、total_epochs=1、save_freq/test_freq=10、保留最近 3 个 actor checkpoint。学习率、vLLM 显存比例、总步数与部分 loop 参数默认是空值，交给下一层解析。
  2. 前端继承与覆盖分开：paramDefaults 合并后端与所选模板的 loop 值，只作 placeholder；params 初始为空，仅存用户输入或 preset。清空字段写 undefined，body 省略 undefined / 空字符串而保留合法零值。换模板更新继承显示，不覆盖显式值；应用 preset 则有意写入一组显式值。模板尚未加载/缺失/失败时阻止继续，不能假装无模板。
  3. 后端 merge 与持久化：merge_params() 从 DEFAULT_PARAMS 起步，拒绝未知 key，忽略 None，对 PARAM_BOUNDS 内字段检查数值范围，并检查 prompt 不长于 model context。create 存的是原始 body.params 和验证后的 plan；submit/render 再次 merge。因此台账不是所有最终默认值的冻结副本，未来修改默认实现可能影响再次渲染。
  4. 落到具体配置：overrides() 从 FIXED 构建受控 Hydra 参数，按 profile/LoRA 分支加入 plan 与训练参数；lr / gpu_memory_utilization 空值回退 planner，mini batch 空值回退 train batch，总步数有值才输出。agent_loop_yaml() 对三项通用 loop 参数按“truthy 显式参数 → 模板 → 通用默认”选择，再选择性传递 history / reward / failure-policy 等模板键；registered sessions 固定为 true。

9.2 成功、失败、取消：清理并不对称

  • 成功：finalize 先摄取产物与费用，再调用 _release_rayjob；该函数捕获删除异常并记日志。只有 scale_down_after=true 才尝试同池缩零，不要求关闭自动缩容才能释放已结束 RayJob。
  • 失败：finish hook 写 Run failed；只有 scale_down_after=true 才走 RayJob 释放与同池缩容尝试，该段异常被吞掉。关闭开关可能保留最终失败 RayJob 和容量；不能说所有失败都会自动清云。
  • 取消：hook 映射为 Run stopped；开关开启时尝试缩容，但 hook 对 cancelled 跳过 RayJob 释放，依赖 monitor 的删除分支。因此阶段边界取消、queued cancel 与 hook 异常均有不同残留风险，详见第 4 章，未做竞态复现。
  • 判闲不是全局资源仲裁：scale_down_if_idle 只查同 cluster / instance_group 的 running、retrying、preparing、waiting_capacity Run；不含 queued，也不遍历推理端点或所有 Pod。guardian 改从 Pod 忙闲判断，是不同保护层，不能把两者合成全局 reconciliation。

RayJob manifest 的 shutdownAfterJobFinishes、600 秒 TTL 与主动 delete 是不同机制；都依赖外部控制器实际执行。删除训练 Job 或将 GPU 数量降零也不会删除 EKS system 节点、FSx、NLB、AgentCore 等全部资源，更不表示所有费用归零。

11.1 术语速查

以下是本文用语的阅读释义；具体实现和限制以对应章节引用为准，不扩展为 toolkit 算法细节或 AWS 保证。

控制面 / 训练面
控制面接受意图、编排和观测；训练面在 GPU/Ray/verl 与 AgentCore 之间执行训练、采样和模型调用。详见 系统总览。
Run / Job / stage / attempt
Run 是训练业务；Job 是一次 pipeline 执行；stage 是 Job 的一个持久化步骤；attempt 是一次外部 RayJob 提交轮次，不是重试 Job 的新 ID。详见 状态轨道。
台账 / 幂等 / reconciliation
台账保存意图与最近观测；幂等是重跑时先查真实状态、避免重复副作用的约定，不是 exactly-once；reconciliation 指持续比较意图与实际状态，本仓库只有未注册回调的引擎框架，不能称全局同步已启用。
GRPO / rollout
GRPO 是本仓库选择的组相对策略优化算法名；rollout 是 Agent 对样本的一次采样轨迹，可包含多轮模型/工具调用。本文只解释其 接入与观测链，不证明算法收敛或收益。
FSDP / Megatron / full / LoRA
前两者是训练后端/并行配置路线，后两者表示全参数或低秩适配器微调；它们组合成 strategy。参见 规划启发式，不是四个互斥算法。
TP / CP / EP / HBM / offload
张量并行 / 上下文并行 / 专家并行；HBM 指 GPU 高带宽显存；offload 指把部分训练状态移到 CPU 等内存。rollout_tp 单独服务推理并行，不自动等于训练 TP。
gateway / vLLM / registered sessions
gateway 是 Agent 模型请求回连的训练侧入口；vLLM 提供模型推理。registered sessions 是只接受预注册会话的输出配置契约，实际实现位于外部 toolkit。不是 FastAPI webhook。
EFA / IRSA / SG / ENI / LBC
EFA 是实例间高性能网络能力；IRSA 将 K8s ServiceAccount 与 IAM 身份关联；SG 是安全组，ENI 是网络接口；LBC 是 AWS Load Balancer Controller。配置声明不能替代真实连通性/权限验证。
checkpoint / index / export
checkpoint 数据在 FSx；S3 index 仅列可见 step；export 才执行模型合并并同步 S3。模型 export 不等于可恢复训练全状态，checkpoint 也不保证永不轮转。
guardian / deadline / budget
guardian 是独立集群 CronJob；deadline 是有配置才写入的单 RayJob 限时；budget 是轮询估算守卫。它们作用域不同，都不是全账户硬账单上限，详见 费用防线。
draft / server snapshot / URL state
draft 是本地未提交编辑；snapshot 是某个 hook 最近取得的数据；URL state 标识页面/资源/tab。轮询和 reload 不构成共享缓存或自动全局失效，详见 前端数据流。
